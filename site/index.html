Three tools, one install

The fix is rarely “delete everything”

Most broken installs have one specific cause. cleaninstall-node finds it, tells you, and fixes only that, so you can skip the five-minute reinstall.

doctor

Checks your Node version, lockfile sync, dependency ranges, native modules and package manager, then suggests the smallest fix. --fix applies it.

git hook

After a pull, branch switch or rebase changes your dependencies, it warns you (or runs the install) before you hit a confusing error.

clean

Workspace-aware removal of node_modules, build output and caches. It shows sizes, asks once, and keeps your lockfiles unless you say otherwise.

doctor

Diagnose first. Fix the smallest thing.

doctor looks at what's actually installed, compares it with what your project asks for, and suggests the least disruptive repair.

Start from the error you got

Pipe any failing command into --from-error. It explains the error for your project: Cannot find module 'axios' gets a different fix when axios is declared but missing, only installed through another package, the wrong version, or your own file.

  • Native modules: ABI mismatch, wrong OS/CPU, missing rollup/esbuild/sharp binaries.
  • Installs: lockfile out of sync, ERESOLVE, engine errors, wrong package manager.
  • Runtime: module or command not found, ERR_REQUIRE_ESM, unexported subpaths.
$ npm run dev 2>&1 | npx cleaninstall-node doctor --from-error

MCP server · for AI agents

Stop your agent from running rm -rf node_modules

When an install breaks, AI coding agents delete node_modules and the lockfile and hope for the best. cleaninstall-node mcp gives them the diagnosis and the smallest fix instead.

  • explain_error and diagnose return what's wrong and a fix plan as structured data.
  • apply_fix and clean need the plan_id from the read-only call, so the plan is shown before anything changes.
  • Hard limits: never runs on / or your home folder, keeps lockfiles, and won't rebuild on the wrong Node.
  • Zero extra dependencies. Works with Claude Code, Cursor, VS Code, Windsurf and Claude Desktop.
$claude mcp add cleaninstall -- npx -y cleaninstall-node mcp

git hook

Know when to reinstall, right when it happens

Someone bumps a dependency and you pull. Nobody reinstalls, and an hour later the build breaks in a confusing way. The hook catches the moment the lockfile changes.

  • Silent unless it matters. If no dependency file changed, or node_modules already matches, you see nothing.
  • Warn or auto-install. --mode install runs the install or a targeted rebuild, and never deletes node_modules.
  • Team-wide with husky. It writes to .husky/ so you can commit it, and keeps your existing hooks.
  • Never breaks git. It's skipped in CI, and CLEANINSTALL_SKIP_HOOK=1 skips it once.
$npx cleaninstall-node hook install 
$ git checkout release/2.4
Switched to branch 'release/2.4'

   (or: npx cleaninstall-node doctor --fix)
clean

When you really want a fresh start, do it safely

Finds every workspace from package.json or pnpm-workspace.yaml and cleans it in one go.

  • Asks once, with the full list and sizes. Use -y in scripts; CI and pipes don't prompt.
  • Keeps lockfiles by default, so a “clean install” doesn't quietly upgrade your dependencies. Use --lockfiles for a full reset.
  • Knows framework output: .next, .nuxt, .svelte-kit, .astro, .turbo, .vite, coverage and more.
  • Reinstalls with the right tool, detected from packageManager or your lockfile.
  • Dry run and interactive modes, plus config in package.json or .cleaninstallnoderc.
